# EnrollingGL — дизайн-спека

Дата: 2026-07-11. Статус: утверждена пользователем (цель MVP, приём заявок,
география, секции, поля анкеты, архитектура — вопросы 1–5 и обе части
дизайна).

## 1. Что строим

Совместный с другом проект помощи с поступлением за границу (в основном
Европа, возможна Азия). MVP — одностраничный лендинг с прокруткой на
русском языке. Задача страницы — не выдавать наработки, а расположить
человека и довести до анкеты; сами консультации проходят потом, лично.

Главный сценарий успеха: посетитель прочитал страницу, поверил, что
поступление реальнее, чем кажется, заполнил анкету — заявка мгновенно
пришла основателям в Telegram, они связались с человеком сами.

После MVP планируется tg-бот как второй канал контакта (в этот MVP не
входит; приёмник заявок — не диалоговый бот).

## 2. Утверждённые решения

| Вопрос | Решение |
|---|---|
| Цель MVP | Сбор заявок через анкету на сайте; связываемся с людьми сами |
| Приём заявок | Telegram Bot API через Cloudflare Worker (токен — в секрете Worker'а, не в коде сайта) |
| География контента | В основном Европа, с оговоркой про Азию |
| Секции | Hero, цифры/факты, о нас/о друге, подводные камни/мифы, FAQ, анкета, футер. Пошаговый гайд по поступлению НЕ делаем — детали на консультации |
| Поля анкеты | Имя*, контакт* (Telegram/телефон), «куда хотите поступать» (необяз.), «ваш вопрос» (необяз.) |
| Стиль | Минимализм kartoshkafrei.ru + сдержанный тон edu-vienna.com |
| Хостинг | Статика на GitHub Pages + бесплатный Cloudflare Worker |

## 3. Стек и ограничения

- Ванильные HTML, CSS, JS (ES-модули). Без npm-зависимостей, фреймворков
  и сборщиков. Node ≥ 20 — только для тестов (`node --test tests/`).
- ES-модули не работают с `file://` — локальный запуск через
  `py -m http.server 8000`.
- Тексты интерфейса русские; идентификаторы кода — английские.
- Worker — один файл JS под Cloudflare Workers (деплой через wrangler или
  веб-интерфейс Cloudflare).

## 4. Архитектура

```
index.html            разметка всех секций
css/style.css         стили (цвета — CSS-переменными)
js/data/content.js    контент: цифры, мифы, FAQ, тексты hero (данные ≠ разметка)
js/core/validate.js   валидация анкеты (чистые функции, без DOM)
js/ui/                рендер секций из данных, аккордеон FAQ, форма
js/app.js             состояние и связывание модулей
worker/worker.js      Cloudflare Worker — приёмник анкеты
tests/                node --test: целостность контента, валидация
```

Контент — массивы объектов в `js/data/content.js`: добавить миф или вопрос
FAQ = дописать объект, не трогая разметку. При появлении бэкенда этот
модуль заменяется на API без переписывания UI.

## 5. Страница (сверху вниз)

Компактное меню-шапка с якорными ссылками на секции, плавный скролл.

1. **Hero** — кто мы и чего хотим добиться: помочь поступить за границу и
   показать, что это реальнее, чем кажется. Крупный заголовок,
   подзаголовок, кнопка «Оставить заявку» (скролл к анкете).
2. **Цифры/факты** — полоса из 3–4 коротких метрик (стоимость семестра,
   программы на английском, длительность процесса — точные значения
   согласуются на этапе контента).
3. **О нас / о друге** — блок про основателя с реальным опытом
   поступления: фото, короткая история, чем может помочь. Тексты и фото
   пользователь предоставит позже — в MVP структура с временным
   заполнителем.
4. **Подводные камни / мифы** — центральная секция: 3–6 карточек
   «страх → как на самом деле».
5. **FAQ** — аккордеон, 5–8 вопросов, короткие ответы; за деталями — к нам.
6. **Анкета** — поля из §2; кнопка «Оставить заявку»; после успеха —
   «Спасибо, мы свяжемся с вами» (форма заменяется на сообщение).
7. **Футер** — ссылка на Telegram основателей, минимум служебного.

**Стиль:** много воздуха, светлый фон, один акцентный цвет, аккуратная
типографика. Тон текста сдержанный и уверенный: без панибратства, без
канцелярита. Конкретные цвета/шрифты выбираются в задаче вёрстки плана.

Адаптивность: страница корректна на мобильном (одна колонка, меню
сворачивается) — значительная часть трафика будет с телефонов.

## 6. Путь заявки

```
форма → fetch POST JSON → Cloudflare Worker → Telegram Bot API sendMessage
                                             → приватный чат/группа основателей
```

Worker:

- валидирует поля повторно (фронту не доверяем);
- берёт `BOT_TOKEN` и `CHAT_ID` из секретов Worker'а — в репозиторий и в
  код сайта они не попадают;
- отвечает JSON `{ok: true}` / `{ok: false, error}`; CORS настроен на
  домен сайта;
- анти-спам: honeypot-поле (скрытый input, заполняют только боты →
  молча отбрасываем) + best-effort rate-limit по IP в памяти Worker'а
  (без КВ-хранилища, сбрасывается при перезапуске — для MVP достаточно).
  Капчи нет — отпугивает людей.

URL Worker'а хранится константой в `js/app.js`.

## 7. Ошибки и краевые случаи

- Пустые имя или контакт — форма не отправляется, поле подсвечивается с
  подсказкой (валидация из `js/core/validate.js`).
- Worker недоступен / нет сети / ответ `ok: false` — под формой сообщение
  «Не получилось отправить — напишите нам напрямую в Telegram» со ссылкой;
  введённые данные не стираются. Заявка никогда не теряется молча.
- URL Worker'а ещё не настроен (пустая константа) — форма работает в
  «демо-режиме»: не шлёт запрос, показывает то же сообщение со ссылкой на
  Telegram.
- Повторная отправка — кнопка блокируется на время запроса.

## 8. Тестирование

- `node --test tests/` без зависимостей — TDD для:
  - `js/core/validate.js`: обязательность имени и контакта, допустимые
    форматы контакта (@username / телефон / email), обрезка пробелов,
    ограничение длины полей;
  - целостности `js/data/content.js`: у каждого мифа есть «страх» и
    «реальность», у FAQ — вопрос и ответ, у метрик — значение и подпись.
- UI и отправка формы — ручные чек-листы в браузере в задачах плана.
- Worker — локально `wrangler dev` или curl-запросом; ручной сквозной
  тест «форма → сообщение в Telegram» перед объявлением готовности.

## 9. Документация (README.md)

Пользователь — новичок в веб-разработке; README подробный, витрина +
учебный конспект:

1. **О проекте** — что это, для кого, скриншот.
2. **Как устроен код** — карта папок, почему контент отделён от разметки,
   мини-словарик: fetch, serverless, worker, CORS, secret, honeypot,
   rate-limit — по строке каждый.
3. **Запуск и тесты** — `py -m http.server 8000`, `node --test`.
4. **How-to для расширения** — добавить миф, вопрос FAQ, метрику; обновить
   тексты о друге.
5. **Деплой пошагово** — GitHub Pages; Cloudflare Worker: создание
   аккаунта, секреты `BOT_TOKEN`/`CHAT_ID`, создание бота у BotFather,
   как узнать chat_id, прописывание URL Worker'а в `js/app.js`.
6. **Дорожная карта** — tg-бот как второй канал, английская версия,
   хранение заявок.

## 10. Не делаем (non-goals)

- Диалоговый tg-бот (после MVP, отдельным сервисом).
- Личный кабинет, регистрация с паролем, БД, админка заявок.
- Английская версия страницы.
- Пошаговый публичный гайд по поступлению с наработками.
- Платежи, интеграции с CRM, аналитика сверх простого счётчика (по
  желанию позже).
